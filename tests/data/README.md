# Conformance fixtures

All FASTA input and expected-output sequence files in this directory are gzip-compressed. Expected outputs should be compared after decompression; gzip container bytes may differ across libraries.

## crAssphage reference

The nucleotide input is accession JQ995537.1, the 97,065 bp crAssphage genome. The protein input contains all 80 `/translation` qualifiers for annotated CDS features in the archived GenBank record (29,522 residues total). The GenBank record was preserved at [linsalrob/crAssphage/JQ995537.gbk](https://github.com/linsalrob/crAssphage/blob/master/JQ995537.gbk), after the original record became unavailable at NCBI. The original publication is Dutilh et al., *Nature Communications* 5, 4498 (2014), [doi:10.1038/ncomms5498](https://doi.org/10.1038/ncomms5498).

For both molecule sets, `*.input.fasta.gz` is the source FASTA and `*.expected.hash.fasta.gz` is the HashFASTA v0.1 output.

## Synthetic regression cases

- `duplicate-id.*`: two different sequences share the original first-token ID; expected output must give them different SHA-256 keys.
- `duplicate-sequence.*`: identical sequences have different original headers; expected output preserves both records and gives them the same key.

## Edge cases (`edge-*`)

Generated by `tests/make_edge_fixtures.py`, which builds each expected output directly from the specification's rules rather than by running an implementation. Re-running it reproduces the committed files byte-for-byte.

| Fixture | What it checks |
| --- | --- |
| `edge-lowercase-whitespace` | lowercase uppercased; space, tab, VT, FF and blank lines removed |
| `edge-crlf-line-endings` | CRLF, CR CR LF and a stray CR inside a header and a sequence line; no CR in output |
| `edge-header-escaping` | `\`, `[`, `]` and already-escaped text in the definition line |
| `edge-header-special` | empty header, `>` and tab inside a header, non-ASCII header bytes passed through |
| `edge-symbols-retained` | `-`, `.`, `*`, `U` and IUPAC/amino-acid codes kept as supplied |
| `edge-wrap-boundaries` | sequences of 1, 79, 80, 81 and 250 residues, including one on a single line |
| `edge-rewrapped-equivalent` | the same sequence wrapped, spaced and cased differently gets one key; a one-base change gets another |
| `edge-comment-lines` | `;` comment lines before the first header, after a header, mid-sequence, between records and at end of file without a newline |
| `edge-blank-lines-no-final-newline` | blank lines before the first header and between records; no trailing newline |

## Invalid inputs (`invalid/`)

Every `invalid/*.input.fasta.gz` must be rejected with a non-zero exit status, an error message, and no output file: empty sequences (middle, last, whitespace-only), sequence data before the first header, non-ASCII, control, NUL and DEL bytes in a sequence, a `;` inside a sequence line, a `;` line that is indented (so not a comment), a record whose only body is a comment, a file of comments only, an empty file, and a file of blank lines only.

## Runtime variants

The shared runner (`tests/run_conformance.py`) also feeds each input as plain text, bzip2 and xz, as multi-member gzip, bzip2 and xz, and as files whose names do not match their content. It confirms that output is always gzip with identical decompressed bytes. It also checks zstd and ZIP inputs are rejected, and that truncated gzip, bzip2 and xz streams are errors.
